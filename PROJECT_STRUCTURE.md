## 1. What the suite is

Three GRC products that share one integration fabric:

| System | Purpose | Framework focus |
|--------|---------|-----------------|
| **AutoAudit** | ISO 27001 audit automation | ISO/IEC 27001 |
| **GRC Pulse** | Risk & Compliance management (the "hub") | ISO 27001, SOC 2, GDPR, NIST CSF, PCI-DSS |
| **Pentest Pulse** | Penetration-test management | OWASP / CWE findings |

**Data flow:** Pentest Pulse findings → sync → GRC Pulse risks → compliance score.

## 2. Two runtime targets (same source, different backend)

The **same `src/index.tsx` source** builds for both targets. A build-time
esbuild plugin + a runtime D1→PostgreSQL adapter make this possible.

| | **Cloudflare (production)** | **On-Prem (this repo's docker/ stack)** |
|---|---|---|
| Compute | Cloudflare Pages / Workers | Node.js (`@hono/node-server`) |
| Database | Cloudflare D1 (SQLite) | PostgreSQL (schemas per app) |
| AI | Workers AI | Ollama / none |
| Storage | R2 | local bucket dir (`EVIDENCE_DIR`) |
| Secrets | Wrangler env | process env at build time |

> **Non-negotiable constraint:** a **default (env-less) build must reproduce
> production strings byte-for-byte** — `SYNC_KEY = grcpulse-sync-2024`, peer
> URLs `grc-pulse.pages.dev` / `pentest-pulse.pages.dev`. On-prem values are
> injected only via env vars at build time. Verified after every source edit.

## 6. Compliance scoring system (Weighted Deduction Model)

The compliance score is **risk-adjusted** and reacts to finding/risk status.

```
Base Score  = implemented / applicable controls  × 100
Deduction   = Σ over each OPEN / in_progress risk, by severity:
                 Critical −5 · High −3 · Medium −1 · Low −0.5
              (in_progress risks penalize at HALF weight)
              capped at 40
Final Score = max(0, round(Base − Deduction))
```

- One shared helper — `computeRiskDeduction()` / `computeComplianceScore()` in
  `grc-pulse/src/index.tsx` — feeds **every** score surface: main Dashboard,
  Compliance Dashboard, Executive Summary, and pull-sync ingest. The score is
  therefore identical everywhere.
- **Severity scale:** GRC buckets `inherent_score` on 0–100
  (≥75 critical · ≥50 high · ≥25 medium · <25 low). Pentest Pulse normalizes
  its findings to this scale before sync:
  `critical→95 · high→75 · medium→50 · low→25 · informational→10`
  (plus a `pentest_severity` field). This fixed the original bug where the
  raw 1–25 (likelihood×impact) scale made every synced finding land in the
  *low* bucket, so closing a finding never moved the score.

**Verified behavior (org-001 Acme):** open a critical finding → score `52 → 47`;
close it → `47 → 52`. Deterministic and reversible.

## 7. Tests

```bash

  SYNC_KEY=ci-strong-sync-key-def456uvw \
  GRC_BASE_URL=http://localhost:3002 PENTEST_BASE_URL=http://localhost:3003 \
```

- `npm test` — unit only (`*.test.mjs`)

## 8. Key implementation notes / gotchas

- **D1→PG runtime adapter** (`docker/shared/d1-pg-adapter.mjs`) rewrites
  SQLite/D1 SQL to PostgreSQL at runtime, incl. `INSERT OR REPLACE/IGNORE →
  ON CONFLICT` (`translateInsertOr`). This is why the same source runs on both
  backends without editing queries.
- **`dist-server/app.mjs` is a gitignored build artifact** — never committed;
  always regenerated by `node build.mjs`. Commit **source** (`src/index.tsx`)
  only.
- **Pentest `EVIDENCE_DIR`** defaults to `/data/evidence`; on machines without
  that path/permission the server fails with `EACCES mkdir` — set
  `EVIDENCE_DIR` to a writable dir.
- **Background server start:** `nohup … &` keeps the foreground attached, so a
  blocking shell may appear to hang; verify with a separate health-check
  (`curl -o /dev/null -w '%{http_code}' http://localhost:<port>/`).
- **GitHub credentials** occasionally write an empty `~/.git-credentials`
  (0 bytes); re-run credential setup and confirm the file is non-empty before
  pushing. The token lacks `workflows` permission — `docker/ci/onprem-ci.yml`
  must be copied to `.github/workflows/` manually to activate CI.

## 9. Workflow

1. Build + test each change locally.
2. Commit to `genspark_ai_developer`, push, update PR #1
   (https://github.com/gamosec/grc-security-suite/pull/1).
3. User runs full-app acceptance test on their on-prem "prime".
4. User reviews the live sandbox apps and reports bugs one at a time.

**Production source files** (`grc-pulse/src/index.tsx`,
`pentest-pulse/src/index.tsx`) are edited **only with explicit authorization**,
and any change must keep the env-less build reproducing production strings.
